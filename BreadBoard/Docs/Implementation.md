# 初期実装

## 使い方

`Assets/Scene.unity` を開く。既存Breadboardに `InteractiveCircuit` を追加済み。

1. ボードを片手で持つ。同期と編集権の取得が完了するまで操作パネルに待機状態を表示する。
2. 反対の手をボード上へ動かす。最も近い穴が基準ピンになり、配置可能なら緑、配置できない場合は赤の半透明プレビューを表示する。
3. 反対の手のトリガーで確定する。押し続けても連続配置しない。
4. `Parts >` を開くと全部品が1段の一覧に並ぶ。項目が多い場合はPrevious / Nextでページを送る。非線形素子は `Model >` からモデルを選ぶ。
5. R/C/LはValue + / Value -でE24系列の次/前の値に変更する。桁の境界も連続し、例として910Ω→1kΩ→1.1kΩと進む。UI選択範囲は1p〜1T（SI単位）。範囲端では停止し、循環しない。SupplyではVoltage + / Voltage -で現在値を1Vずつ変更する。確定済み部品のEditと電源変更はその都度同期する。
6. 部品の配置プレビューは手の向きへ90度刻みで常時追従する。Hand切替とRotateボタンは廃止した。45度近辺ではヒステリシスを設ける。
7. Wireは最初のトリガーで始点、次のトリガーで同じ行/列の終点を指定する。長さと方向は両端から決める。Cancel wireで始点を取り消す。
8. Eraseでは端子穴を選んで削除する。Editでは端子穴で部品を選択してからパネルで定数・モデル・向き・ワイヤー長を変更する。

デスクトップ用に、視線とボード面の幾何学的交点を使う補助操作も用意している。部品やパネルの判定にCollider/Physics.Raycastは使用しない。本体の既存Pickup、Collider、Rigidbody、VRCObjectSyncは維持している。

## モデル・電源・容量

- FBXの300中央穴（A〜J、1〜30）と4本×25穴のレールを採用。中央はA〜E、F〜Jをそれぞれ行単位で接続する。
- 初期値は両方の赤レールを共通+5V、両方の青レールを共通GNDとする。固定電源は穴を占有せず、配置・削除の対象にならない。
- `BreadboardLayout` の `supplyVoltage`、`positiveHole`、`groundHole`、`conductorGroups` で初期電圧と内部導通を設定する。現在の電圧はStateに保持し、Supply UIから確定するとJSONで共有する。同梱する初期設定や導通を変更する際はlayout版も更新する。
- 回路データの部品上限は128個。表示GameObjectはPrefabから必要時に生成し、プレビューは最大1個を保持する。State容量分の参照配列は確保するが、表示の事前プールは生成しない。
- JSON上限は60,000文字。全体を検証してから採用し、上限超過の編集は元へ戻す。
- DはGeneric / Low-leakageの2種類の説明用モデル。Qは既存MNAのKSC1815固定モデルのみ。実在部品の特性保証を意味しない。
- QのmodelIdは保存するが、現在のMNAへは従来どおり空のconstantsを渡す。外部モデル対応は後で `BreadboardCatalog.MnaConstants` に追加できる。

## モジュール

| 場所 | 責務 |
| --- | --- |
| Runtime/Geometry | 穴ID、座標、内部導通、最寄り穴 |
| Runtime/Catalog | 部品、フットプリント、値候補、モデルとMNA定数 |
| Runtime/Core | 確定状態、ID、穴占有、追加・削除・変更 |
| Runtime/Placement | 端子位置の計算と全端子の配置判定 |
| Runtime/Serialization | JSON全体の読書きと構造・参照検証 |
| Runtime/Networking | Manual同期、revision、再送、編集権の引渡し |
| Runtime/Circuit | 内部導通とWireの統合、削除後の再構築 |
| Runtime/Simulation | 固定電源と部品をDataList化しMNAGenへ渡す |
| Runtime/Rendering | 部品ID単位のPrefab動的生成、基底クラス経由の表示更新、半透明プレビュー |
| Runtime/Interaction・UI | 反対の手の入力、手の向きによる回転、2点ワイヤー、ページ付きメニュー、E24/1Vステップと右スティック入力 |
| Editor | シーン生成とデータパイプライン検証 |

同期するのは確定部品の穴ID・向き・値/モデル等を含むJSON全体と編集権情報。プレビューや各部品のTransformは同期しない。送信失敗は再送し、古い送信完了で新しい編集の待機状態を消さない。通常の持ち替えは現在の所有者が最新状態と許可（対象プレイヤー・revision・受け渡し番号）を送信し、相手の検証・適用後のACKを受けてからCircuitSyncの所有権を渡す。送信完了だけでは渡さない。要求者はネットワークイベントの送信者と本体の所有者の一致で確認し、遠隔クライアントのPickup.IsHeld/currentPlayerには依存しない。要求・ACKは待機中に再試行する。古い番号のACK、送信待ち、最新revisionと不一致のACKでは移譲しない。

導通は確定変更時に再構築する。浮遊回路・短絡等の電気的診断は行わず、既存MNAGenへそのまま渡す。測定点はBreadboardProbesが穴IDから現在のノード名に変換して、既存Testのプローブ入力欄へ渡す。波形計算・シミュレーション時間・履歴の管理は既存MNA側が担当する。

## 再利用

`Prefabs/InteractiveBreadboard.prefab` を使用できる。配置したPrefabの `BreadboardMnaAdapter.generator` にシーンのMNAGenを設定する。複数ボードを置く場合は各CodecのboardIdと接続先MNAGenを分ける。Prefabは外部シーン参照を保持しない。

未導入の既存シーンでは `Tools > Breadboard > Install in current scene` が、Breadboardという名前のPickup付き本体へ同じ構成を生成する。導入済みの場合は既存構成の誤上書きを防ぐため停止する。

## 確認結果（2026-09-25）

- Unity C#、12個の新規Udonプログラムをコンパイル済み。
- `Tools > Breadboard > Verify data pipeline`：674アサーション成功（E24の全24値・桁境界を含む）。400穴のID/座標、占有、複数端子の拒否、Wireの推移的統合と削除後の分離、JSON往復・不正データ保持、固定電源、float型定数、モデル境界、容量を確認。
- PlayモードのUdon VMで初期状態からMNAへ渡ること、入力の立ち上がりで1個だけ配置されること、同じ押下の重複実行でも増えないこと、確定後revisionがMNAへ反映されること、不正/重複JSONで状態が壊れないことを確認。
- 受け渡し処理の修正後、送信未完了・別プレイヤー・旧revision・旧受け渡し番号・再持ち替えを含む12アサーションを追加し、全674アサーションとUdonコンパイルを確認した。ネットワーク配送と実際の所有権移譲の確認は複数クライアントで別途必要。
- ClientSimでは送信完了とPickup・入力を模擬してローカル経路を確認した。これは実ネットワークの成功を意味しない。
- ClientSim起動時にSDK内部の `IsNetworkingSupported cannot be changed after the UdonBehaviour has been initialized` が発生する。導入前のシーンのコピーでも同じ例外を再現し、今回の機能とは別の既存環境の問題であることを確認した。
- VR実機での左右持ち替え、メニュー時の入力中断、複数クライアントの途中参加・所有権移譲・通信失敗・退出復旧は未検証。詳細シナリオはAcceptance.mdに記載。

右スティック上下はRLCの現在値、Supply画面では電圧に割り当てる。0.65以上倒すと1段変え、0.45秒保持後は0.15秒間隔で繰り返す。0.25未満で停止する。持ち替え・メニュー切替後は一度中央へ戻す必要がある。Wire・モデル一覧・Erase・プローブ操作では数値を変えない。デスクトップのマウス視点入力は対象外。VRChat標準の視点・移動機能は無効化していないため、実機で入力設定との相性を確認する。

自動検証でE24全値、桁境界、上下限、旧来の系列外値からの増減を確認済み。PlayモードのUdon VMでも、1段の部品一覧、E24上下ボタン、軸入力の中立域・増減・再入力条件、電源±1V、Wire操作との分離を模擬入力で確認した。VR実機でのスティックの操作感は未検証。

手の向きは `BreadboardController.handRotationAxis`（初期値は手のローカル横軸）を盤面へ投影して求める。ほぼ盤面法線を向くときは直前の方向を保つ。追従するのは配置前のプレビューであり、既に確定した部品が手の動きだけで回転することはない。Wireの向きは両端指定を優先する。

カタログのkindLabelsで一覧表示名を設定する。カテゴリ階層は設けない。モデル一覧もカタログから生成する。新しい素子種を追加する際は、その形状やMNA変換の実装も別途必要。

既存PrefabのUIだけ更新するEditorメニューは `Tools > Breadboard > Upgrade prefab UI`。現在のPrefabとシーンには反映済み。

シーンは空の編集状態で保存している。検証用の部品や送信完了の模擬処理は製品シーンに残していない。


## CH1 / CH2プローブ

ホームのCH1（黄色）またはCH2（水色）を選び、測定したい穴へ手を動かしてトリガーで指定する。占有済みの穴も指定できる。Clear CH1 / Clear CH2でそのチャンネルだけ解除する。Placeへ戻すと部品配置を再開する。

測定点はボードの共有設定として穴IDで保持する。CH1/CH2の穴ID（空文字は解除）と専用revisionをCircuitSyncのManual同期に含め、Remote・途中参加・持ち替え時にも引き継ぐ。操作できるのは編集権を取得した保持者。部品を追加せず、穴を占有せず、回路revisionやJSONも変更しない。Wireの追加・削除後は同じ穴が属する新しいノードへ追従する。新しいMNA入力の適用待ちでは古いノード指定を一旦解除する。

既存オシロスコープの入力処理に、未接続・未指定なら非表示、GNDなら0Vの表示を追加した。負の行をデータバッファに渡さない。履歴やシミュレーション時間をリセットする処理は追加していない。通常の手入力プローブも引き続き使えるが、穴への追従を解除したい場合は先にClearする。

シーンのBreadboardProbes.channel1Input / channel2Inputは既存Testの入力欄に接続済み。Prefabを別シーンに配置する場合は、MNAGenに加えてこの2つの入力欄を割り当てる。`BreadboardBuilder.BindProbes` は既存Testから参照を取得できる。

追加の自動検証で2チャンネルの独立指定、Wire統合・分離後の追従、更新待ちでの古い指定解除、GND、片側だけの解除、回路状態が変わらないことを確認済み。PlayモードのUdon上でも、CH1の電源測定、CH2のGND指定、片側解除、Wire追加後のノード変更が既存入力欄に反映されることを確認した。VR実機の指しやすさは別途確認が必要。

プローブ同期修正：回路revisionが同じ受信でも測定穴・マーカー・既存オシロスコープ入力を更新する。古い測定revision、不正な穴、同revisionの異なる内容は適用しない。送信完了で新しいプローブ変更の送信待ちを消さず、受け渡しの確認番号も更新する。観測変更だけではMNAの再構築や波形履歴のリセットを行わない。自動検証に受信・解除・重複・旧版・不正データ・送信項目の10項目を追加。実ネットワークの複数クライアント確認は未実施。

## Prefabによる動的表示（2026-09-26）

`BreadboardPart` を共通基底クラスとし、現在の簡易形状は派生クラス `BreadboardSimplePart` で描画する。`Prefabs/Parts/` にWire/R/C/L/D/Qの6個の非アクティブPrefabを用意した。詳細と追加方法は [DynamicParts.md](DynamicParts.md) を参照。既存シーンとInteractiveBreadboard Prefabは移行済み。

既存データ検証674項目に加え、PlayモードのUdon VMで47項目（6種の生成、virtual呼出し、部品ID維持、値更新、削除、プレビュー切替・再利用・回路非変更）を確認。次フレームの破棄と表示も確認した。ClientSimの初期スナップショット適用を表示テストから分離しているため、複数クライアントでの通信試験を代替しない。テスト終了後はPlayを停止し、テスト回路を保存しない。
