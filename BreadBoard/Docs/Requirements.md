# 要件定義

作成日：2026-09-25。状態：レビュー反映版。利用者から明示された要件と、実装可能な形にするための初期案を区別する。

## 1. 目的と範囲

ブレッドボード上の配置操作を回路入力に使い、`Test.cs` が扱うテキスト欄へのネットリスト入力を置き換える。配置情報から接続を生成し、`MNAGen.netlist` と `MNAGen.UpdateMNA()` を通して既存の `MNASolve` にシミュレーションさせる。

| ID | 利用者からの確定要件 |
| --- | --- |
| U-01 | 片手でボードを持つと、反対の手に最も近い配置位置へ部品を半透明表示する。 |
| U-02 | 反対の手のトリガーで部品の配置を確定する。左右どちらの手でもボードを持てる。 |
| U-03 | 部品の配置判定・部品の同期にColliderやVRCObjectSyncを使わない。部品ごとのTransformを同期せず、刺さっている穴の位置等をテキストで送る。 |
| U-04 | **ボード本体の保持には既存のPickupを利用してよい。** 本体のCollider・Rigidbody・VRCObjectSyncと、部品の配置・同期は分けて扱う。追加確認に対する利用者回答による。 |
| U-05 | ボード上の簡単なUIから部品種別、受動素子の素子定数、非線形素子のモデル、ワイヤーの長さを選べる。 |
| U-06 | ワイヤーでつながる接続点を内部的に統合し、MNAへ渡す。 |
| U-07 | 関連リソースは `Assets/Breadboard` 配下に集約し、分離できる責務はモジュールに分ける。 |
| U-08 | 電源はボードの電源ラインに最初から備え付ける。電源を個別の配置部品にしない。 |
| U-09 | 回路の有効性判定・無効な回路への対応、波形の保持・表示はMNA側に任せる。Breadboard側で計算の保留・拒否や履歴のリセットを行う要件は設けない。 |
| U-10 | 非線形モデルの入力拡張は後からMNA側で実装する。Breadboard側はモデル情報を保持し、連携部分を後から拡張できる構成とする。 |

この初稿ではPC VR・1枚の共有ボード・1人ずつの編集を初期案とする。複数人は同じ確定回路を閲覧できる。Android/Quest、デスクトップ操作、複数人の同時編集、インスタンスをまたぐ永続保存は後続拡張とする。モジュール境界はこれらの拡張を妨げない。

## 2. 保持・配置操作

| ID | 要件 |
| --- | --- |
| IN-01 | 本体のPickup状態から保持者と保持している手を判定する。保持者の反対の手だけを編集入力として扱う。手を持ち替えたら入力側も切り替える。 |
| IN-02 | 手の座標をボード面のローカル座標に変換し、定義済みの穴位置との距離から候補を決める。Physics.Raycast、Overlap、接触イベント、穴ごとのColliderを使わない。 |
| IN-03 | 「最も近い」は部品の基準ピンに対する最寄りの実在穴とする。同距離は穴の固定順で決め、境界でのちらつきを抑える小さなヒステリシスを持つ。空き穴へ勝手に飛び越えない。 |
| IN-04 | 操作距離、ボード表側からの高さ、ボード外周の範囲を満たす場合だけ候補を出す。裏側・遠距離・手の位置取得不能・未保持・編集権限待ちでは配置しない。閾値は設定値とし、実機で調整する。 |
| IN-05 | 選択した部品の形状・向き・ピン位置を半透明で表示する。配置可否を色と短い理由で表示する。不正候補は確定できない。プレビューは操作者のローカル表示とする。 |
| IN-06 | 反対の手の `InputUse` の押下エッジ1回につき、表示中の候補を1個だけ確定する。押し続け、UIからの押下継続、保持開始時の押下継続では追加しない。[公式入力イベント](https://creators.vrchat.com/worlds/udon/input-events/) |
| IN-07 | 押下時に候補・ピン占有・権限・容量を再検証する。押下から確定までの途中で別の穴へ移動しても、未表示の位置に確定しない。 |
| IN-08 | 全ピンの配置が1回の操作で成功するか、全体が不成立になる。穴欠落、同一穴への複数ピン、他部品のピンとの重複、範囲外、未対応部品は拒否する。 |
| IN-09 | ボードを離す、保持者が退出する、所有権を失う、メニュー等で操作が中断する場合は、未確定プレビューと押下状態を破棄する。 |

部品方向はボード面内の4方向とし、配置中は反対の手の向きへ90度単位で追従する。境界ではヒステリシスを設け、手の基準軸が盤面法線に近い場合は直前の方向を保つ。手の追従は常時ONとし、切替・Rotateボタンは設けない。方向は見た目だけでなくピンの順番に反映する。DのA/K、QのC/B/Eをプレビューと確定表示の両方で確認できる。備え付け電源の接続先と極性はボードの電源ラインに表示する。

ワイヤーは初期案として「穴ピッチの整数倍の、ボード面の縦または横にまっすぐ渡すジャンパー」とする。始点穴、終点穴を順にトリガーで選び、両端の位置から長さと向きを決める。始点だけでは部品を確定・同期しない。表示には必要な浮き・曲がりを付けても、接続は両端だけで決まる。自由曲線と斜め配線は拡張とする。

ピン占有と部品本体の占有は分ける。ワイヤーの下の穴を一括占有せず、交差するワイヤーも自動導通させない。部品本体の重なりを制限する場合は、カタログの2D占有領域と高さ区分による数値判定を使う。

## 3. ボード上のUIと編集

| ID | 要件 |
| --- | --- |
| UI-01 | UIはボードに追従し、部品選択、必要なパラメーター、向き、編集モード、配置可否、同期状態を小さくまとめて表示する。 |
| UI-02 | R/C/LはSI単位を明示した値選択を提供する。例：Ω・kΩ、pF・nF・µF、µH・mH。単位付き表示を正規化して数値として保存する。 |
| UI-03 | D/Qなどは対応モデルの一覧を表示し、モデルIDと版を保存・同期する。選択肢は現行MNAが扱えるモデルから開始し、MNA側のモデル入力拡張後に追加できるようにする。 |
| UI-04 | ワイヤーは2点指定で穴ピッチ単位の長さを決める。V/Iの配置項目は設けない。電源ラインとGNDの割当はボード定義に持たせる初期案とし、利用者がGND部品を配置する操作は設けない。 |
| UI-05 | 配置モードと削除モードを持つ。削除対象は穴と部品IDから数値的に選択する。配置済みの値・モデルを変更できる。これらも1回の回路更新として同期する。 |
| UI-06 | UIを操作したトリガーを部品配置にも使わない。入力の優先順位はUI、選択中の編集操作、配置の順。1押下の二重使用を防止する。 |
| UI-07 | 部品UIの初期案は、手の位置とUI矩形の数値判定による近接操作。Canvas/TMPを表示に利用できるが、部品入力用Colliderは追加しない。本体Pickup用Colliderは部品の判定へ流用しない。 |

Undo/Redo、一括移動、コピー、自由なSPICEテキストの読込・書出しは初期必須には含めない。最低限の修正操作は削除・再配置・パラメーター変更で成立させる。

## 4. 回路と対応部品

| ID | 要件 |
| --- | --- |
| CIR-01 | 穴には安定したID、ボード内の位置、内部導通グループを定義する。中央溝、電源レールの分断、穴がない場所をデータとして表現する。見た目の近さだけで導通させない。 |
| CIR-02 | 内部導通グループを統合した後、全ワイヤーの両端を推移的に統合する。R/C/L/D/Qの各端子や、固定電源の正負ラインを素子の存在だけで統合しない。 |
| CIR-03 | ワイヤーを削除したら導通を元データから再構成し、再び独立したノードに分離できる。統合済みの集合だけを回路の正本にしない。 |
| CIR-04 | ボード定義でGNDに割り当てた電源ラインのノードを `GND` とする。固定電源とGND割当は穴を占有せず、同じラインの穴へ通常の部品・ワイヤーを挿せる。 |
| CIR-05 | 配置部品の初期対応はワイヤー、R、C、L、D、NPNのQ。固定電源はボード定義からMNA入力へ組み込み、配置・回転・削除の対象にしない。MOSFET、PNP、IC等は後続拡張とする。 |
| CIR-06 | 穴ID・ピン占有・数値型など、配置とデータ形式の妥当性を確認する。短絡、浮遊ノード、電源/GNDへの未接続、部品がない状態などの電気的な有効性は判定せず、その接続をMNAへ渡す。 |

部品カタログは形状・ピン配置・MNA端子順・値の範囲・モデルIDと版を持つ。Dは現行の `Is, Vt` に対応するモデル、Qは現行KSC1815相当から開始する。Qの外部モデル入力は後続のMNA側の作業とし、Breadboard側ではモデル参照と変換処理を分離しておく。MNA未対応のモデルを別モデルへ黙って置き換えない。

固定電源の接続先と初期電圧はボード設定で定義する。利用者はSupplyの上下操作で電圧を1Vずつ変更する。現在の電圧は回路JSONに含めて同期する。レールが分断されている場合、どの区間に給電するかも明示する。具体的な設定値は実ボードの定義時に決める。

## 5. 同期・所有権

| ID | 要件 |
| --- | --- |
| NET-01 | 編集状態の正本は「部品ID・種別・端子ごとの穴ID・値/モデル・向き/長さ」とボード定義のID・版を持つ回路ドキュメント。固定電源の接続先とGND割当は参照先のボード定義に含め、現在の電圧は回路ドキュメントに含める。GameObject、Transform、プレビュー、GPUバッファは正本に含めない。 |
| NET-02 | 初期案はManual同期の文字列変数にJSONの全体スナップショットを格納する。確定変更時に送信し、毎フレーム送らない。途中の変更がまとめられても最新の全回路を復元できる。[Manual同期](https://creators.vrchat.com/worlds/udon/networking/network-details/) |
| NET-03 | 受信時は全データを検証してから一括適用する。失敗時は最後の正常な回路を保持する。同じrevisionの重複適用で部品を増やさず、古いrevisionで巻き戻さない。 |
| NET-04 | 途中参加者は最新の同期変数から回路と表示を復元する。部品配置イベントの履歴再生だけに依存しない。[途中参加の同期](https://creators.vrchat.com/worlds/udon/networking/late-joiners/) |
| NET-05 | 同時に変更できるのはボードの保持者1人。Pickupの所有者と回路同期の所有者を一致させ、双方の権限と最新状態の取得が確認できるまで編集を許可しない。取り合いで所有権を失った側の保留操作は適用しない。 |
| NET-06 | 通常の持ち替え・受け渡しでは送信待ちを処理してから編集権を渡す。revisionを引き継ぎ、初期値で上書きしない。退出時はネットワークに残った正常な状態から復旧する。 |
| NET-07 | ローカル反映済み・送信待ち・送信成功・同期エラーを区別する。送信失敗/混雑時は最新スナップショットを保持し、間隔を置いて再送する。新しい変更を古い再送で上書きしない。 |
| NET-08 | JSON長、最大部品数、プール容量、モデル版、ボード版を検証する。上限超過は操作の確定前に説明付きで拒否する。初期版は単一スナップショットに収め、分割送信は別仕様にする。 |

「確実な同期」の受け入れ条件は、通信可能な状態で最新の送信が成立した後、同じrevisionを受け取った全員の部品情報・接続・生成ネットリストが一致し、途中参加でも復元できること。`OnPostSerialization.success` は送信試行の結果であり、全参加者の適用確認という意味にはしない。[送受信イベント](https://creators.vrchat.com/worlds/udon/networking/network-components/)

送信前に保持者が切断したローカル変更まで保証するには別の確認応答・確定プロトコルが必要であり、初期版の保証範囲外とする。この場合も最後に共有できた状態は壊さず、未共有の操作を共有済みと表示しない。インスタンス終了後の永続保存もJSON同期とは別機能とする。

## 6. MNAへの入力と責務の境界

| ID | 要件 |
| --- | --- |
| SIM-01 | 確定/受信した回路から接続を生成し、配置素子と固定電源を合わせた `DataList [name, nets, constants]` の配列を `MNAGen` に渡す。固定電源は各更新で1回だけ含め、追加を累積させない。 |
| SIM-02 | WireとGND割当自体はMNA素子にしない。DはA/K、QはC/B/E、固定電源は正負の端子順を維持する。配置部品IDと固定電源IDから重複しないMNA名を生成する。 |
| SIM-03 | 回路の可解性、短絡、特異行列、非収束などはMNA側の責務とする。Breadboard側ではこれらを理由に入力を拒否・保留・修正したり、専用の診断表示を追加したりしない。 |
| SIM-04 | 確定変更時にMNA入力を更新する。手の移動やプレビュー更新だけではMNAへ再入力しない。配置・データ形式が成立していれば、組み立て途中の接続もそのまま渡す。 |
| SIM-05 | 計算の初期化、時間、状態・履歴の継承、再始動はMNA側に任せる。Breadboard側の変更でリセット方針を追加しない。 |
| SIM-06 | 波形の保持・表示、プローブ、表示倍率、計算ステップ・誤差設定はMNA側の既存機能に任せる。Breadboardモジュールには移植しない。 |
| SIM-07 | 置き換える範囲は `Test.restart()` 相当の回路入力。`Test.Update()` 等の既存の観測・計算制御は今回の分割対象に含めない。モデル解決の連携部分はMNA側の将来拡張に合わせて変更できるようにする。 |

同期対象は配置回路であり、各クライアントのMNAへ同じ入力を渡すところまでをBreadboard側の責務とする。計算結果・時刻・履歴・波形の同期や表示方法は本仕様では定めない。

## 7. 性能・実装時に確定する値

- RuntimeはUdonSharpで実装し、JSONは `VRCJson` を使う。部品表示は再利用可能なローカルプールを基本とする。実行中に穴ごとのGameObject/Colliderを生成しない。
- 毎フレーム処理は入力・候補判定・表示更新に限定する。JSON生成・解析、導通計算、MNA再構築は確定変更単位で行う。
- 配置部品数、表示プール容量、シリアライズ実測byteCountを管理する。MNA内部の未知数やGPUメモリー管理はソルバー側に任せる。
- 初期容量案は128部品。確定値はJSON量、プール、配置処理の実機性能に合わせる。穴ピッチ・列数・レール分割と固定電源の割当・操作距離・最大ワイヤー長・具体的モデル一覧は実モデル照合後に設定する。
- ClientSimはローカル確認に使い、左右のVR操作と途中参加・受け渡し・退出復旧は複数の実クライアントで確認する。

## 8. 現状との差分

- 調査環境はUnity 2022.3.22f1、VRChat Worlds SDK 3.10.2、Built-in Render Pipeline。アクティブシーンは `Assets/Scene.unity`。
- 本体にはPickup/Collider/Rigidbody/VRCObjectSyncがあり、継続利用可能。部品側へこの方式を増やさない。
- `Board.cs` は穴配列と配置可否の試作、`ComponentManager.cs` は矩形計算の試作。配置・同期・回路生成は未完成。両者で方向のコメントも一致していないため、新データ仕様で統一する。
- `Test.restart()` は手入力をパースして `MNAGen.netlist` を埋める。`Test.Update()` は表示と計算設定も担当している。
- `MNAGen` はR/C/L/V/I/D/Qを扱うが、Breadboardの配置部品はWire/R/C/L/D/Qに限定する。Dの値は外部入力、Qのモデル定数は現状固定で、拡張は後からMNA側で行う。`MNASolve.ChangeCircuit()` の履歴処理は既存の責務として維持する。
- 旧 `Assets/TODO.md` の「JSON保存をやめる」「GameObjectをデータに含める」案は今回の要件で置き換える。表示参照はローカルキャッシュに分離する。

## UI更新要件

部品種別は1段のページ付き一覧で選ぶ。モデル一覧も同じ方式で選択できる。RLCはE24系列、電源電圧は1V刻みの上下ボタンを使う。右スティック上下も同じ増減へ割り当てる。配置前の値はローカル、確定部品のEditと電源の変更はその都度同期する。Wireの2点入力は維持する。
