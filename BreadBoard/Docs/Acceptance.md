# 受け入れ条件

以下は今後の実装に対する合格基準であり、今回の要件定義作成によって実機合格済みとするものではない。

## 操作・UI

| ID | シナリオ | 合格条件 |
| --- | --- | --- |
| A-01 | 左手/右手で本体を持ち、反対の手を動かす。 | 正しい側の手に最も近い穴へ半透明部品が追従し、持ち替えにも対応する。 |
| A-02 | 反対の手でトリガーを押し、押し続け、離して再び押す。 | 1押下につき1回だけ確定する。保持側のトリガーでは配置しない。 |
| A-03 | 裏側・遠方・外周外・占有済み穴・穴欠落へ手を動かす。 | 無効候補の表示/非表示が定義どおりで、誤配置も配列範囲外アクセスもない。 |
| A-04 | 多端子部品の1ピンだけが配置不可の位置で確定する。 | 部品全体が拒否され、部分占有が残らない。 |
| A-05 | UIで値・モデル・向き・ワイヤー長を変更し、同じトリガーを押したまま盤面へ戻す。 | 部品選択に応じた項目が表示され、UI操作が部品配置を兼ねない。 |
| A-06 | D/Qを回転して配置する。 | 表示された極性/端子名とMNA端子順が一致する。 |
| A-07 | 削除・値変更・モデル変更を行う。 | 対象部品IDだけを更新し、占有と計算へ反映する。 |
| A-08 | ボードを離す、メニューを開く、入力取得を中断する。 | プレビューが消え、復帰時の押下持越しで部品が増えない。 |
| A-09 | 生成された部品Prefabと配置判定経路を調べる。 | 部品にCollider/VRCObjectSync/Pickupがなく、物理判定に依存しない。本体Pickupは動作する。 |
| A-28 | ボードの初期状態と部品選択UIを確認する。 | 電源は定義された電源ラインに備え付けられ、V/Iの配置・回転・削除項目がない。固定電源やGND割当が穴を占有しない。 |

## 回路・MNA

| ID | シナリオ | 合格条件 |
| --- | --- | --- |
| A-10 | 同じ内部導通列、中央溝の両側、分断レールに端子を置く。 | BoardLayoutどおりの接続となり、見た目だけで別ノードが統合されない。 |
| A-11 | A–B、B–Cをワイヤーで接続し、そのうち1本を削除する。 | 推移的に1ノードへ統合され、削除後に必要なノードへ再分離する。 |
| A-12 | ワイヤーを交差させる、同じノードの穴同士を結ぶ、配線をループにする。 | 交差だけで導通せず、冗長配線・循環で重複素子や無限処理が生じない。 |
| A-13 | R/C/L/D等の部品を2ノード間に置く。 | 部品をワイヤーと誤認して両端を統合しない。 |
| A-14 | DataContractの固定電源5V・1kΩ＋1kΩ回路を生成する。 | 固定電源1件と配置抵抗2件のDataListが指定どおり生成される。編集用JSONに電源部品がなく、再入力で電源が重複しない。 |
| A-15 | R/C/L/D/現行Qと固定電源の構成を、手書きTest入力で生成したデータと比較する。 | 端子の対応と定数が一致する。計算結果・波形の検証はMNA側の範囲とする。 |
| A-16 | D/Qのモデル参照を保存・同期・復元し、MnaAdapterへの受渡しを確認する。 | modelIdと版が保たれる。現行MNAへの変換がモデル解決箇所に分離され、後続のMNAモデル入力をここに追加できる。現段階でQの外部モデル入力実装を必須としない。 |
| A-17 | 未接続・浮遊ノード・電源ラインの短絡などを含む、配置とデータ形式は正しい入力を確定する。 | 接続をそのままMNAへ渡す。Breadboard側で回路の有効性を診断せず、専用の拒否・保留・警告表示を追加しない。 |
| A-18 | ワイヤーで穴を電源/GNDラインへ接続し、その後削除する。 | 現在の導通に応じたノード対応を生成する。プローブ指定は穴IDから現在ノードへ再解決する。波形計算・履歴はMNA側に任せる。 |
| A-19 | 回路構成を変更し、最後に配置部品をすべて削除する。 | その都度MNA入力を更新し、全部品削除後も固定電源は1回だけ含まれる。Breadboard側から履歴・時間のリセットや波形操作を追加しない。 |

## 同期・堅牢性

| ID | シナリオ | 合格条件 |
| --- | --- | --- |
| A-20 | 2人で追加・削除・値変更を共有し、3人目が途中参加する。 | 同じrevisionの部品ID、端子穴、値、モデル、接続、MNA入力が一致する。 |
| A-21 | 同じ状態を再受信し、古いrevisionも受信させる。 | 重複生成・巻戻り・MNA再構築の連発がない。 |
| A-22 | JSONの途中切れ、入れ子の型違い、未知穴、重複ID、NaN相当の入力、版違いを与える。 | 最後の正常なStateを保持し、無効な一部だけが反映されない。 |
| A-23 | 送信失敗/混雑中に追加編集を行い、その後通信を回復する。 | 最新全体を再送して収束する。古い送信完了で最新の送信待ちを消さない。 |
| A-24 | 所有者A→B→A→Bへ、編集する場合/しない場合の両方で渡す。ほぼ同時のPickup、送信完了より遅い受信、遅延/重複ACKも試す。 | 初期同期/所有権待ち中は編集不可。受信・適用のACK後に移譲し、正当な保持者1人だけが最新状態からrevisionを進める。古いACKで移譲せず、再試行で操作を再開できる。 |
| A-25 | 送信待ちがある保持者が退出する。 | 共有済みの正常状態を保持して復旧し、未共有変更を共有済みと誤表示しない。空回路へ戻さない。 |
| A-26 | 設定容量の直前/上限/超過まで部品を追加する。 | 配置/同期の上限超過を確定前に拒否し、正常状態と表示を保持する。JSON実測量とプール量を記録する。 |
| A-27 | 手を動かすだけでしばらく操作する。 | JSON送信、導通再構築、MNA再構築が毎フレーム発生しない。 |

接続とデータ検証は固定入力による自動確認に向く。操作はVR実機、同期は複数VRChatクライアントで確認する。ClientSim単独の成功を、途中参加・所有権移譲・ネットワーク復旧の合格判定にはしない。
